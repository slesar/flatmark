# Missing UTF-8 encoding breaks scripts on Windows

Several `open()` calls lack `encoding="utf-8"`:
- `board.py` reading tickets and writing `BOARD.md`
- `new.py` writing the new ticket

On Windows the default locale encoding (e.g. cp1252) cannot encode `⏳` or the tree characters
(`├──`), causing `UnicodeEncodeError`, and non-ASCII ticket content may be misread.

Acceptance criteria:
- [x] All text file I/O explicitly uses `encoding="utf-8"`.
- [x] Output files use `newline="\n"` for consistent line endings across OSes.
- [x] Covered by the Windows CI job (see T5).
