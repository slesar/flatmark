# Prevent ticket ID collisions across parallel agents and branches

Sequential IDs are allocated by scanning local files. Two agents (or developers) working on
separate branches will both create e.g. `T5`, causing merge conflicts or duplicate IDs (B9).
This is the main scaling risk for multi-agent workflows.

Options to evaluate:
- Optional hash/short-random ID scheme (e.g. `T-7f3a`), configurable per project.
- Branch-aware suffixes.
- Documented convention: allocate IDs only on the main branch.

Acceptance criteria:
- [ ] Decision documented (spike result in this ticket).
- [ ] Chosen scheme implemented behind a config option; sequential remains the default.
- [ ] Natural sorting and board rendering work with the new scheme.
