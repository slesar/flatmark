# Use git mv when archiving tickets to preserve rename history

When archiving tickets (`tickets/<ID>.md` → `archive/<ID>.md`), plain filesystem moves (`mv`)
leave the old file as deleted (`D`) and the new file as untracked (`??`) until staged. Using
`git mv` stages the rename immediately and preserves `git log --follow` history.

Acceptance criteria:
- [ ] Update `AGENTS.md` and `README.md` archiving instructions to explicitly recommend
      `git mv flatmark/tickets/<ID>.md flatmark/archive/<ID>.md` (and note keeping edits minimal
      in the archive commit so Git's similarity check stays above 50%).
- [ ] When implementing `flatmark.py done <ID>` and `flatmark.py obsolete <ID>` (F3), use
      `git mv` if inside a Git worktree (and the file is tracked), falling back to `os.replace`
      otherwise.
- [ ] Test both the Git-tracked and non-Git fallback paths.
