# Separate distribution payload from repository dev files

The repository root currently doubles as the source and as an installed FlatMark instance
(`tickets/`, `archive/`, `BOARD.md`, `AGENTS.md`). This is confusing: the root `AGENTS.md`
describes how to *use* FlatMark, but agents developing FlatMark itself read it as their
instructions.

Proposed layout:

```text
flatmark/                     # repo
├── src/flatmark/             # payload copied by install.py
│   ├── AGENTS.md
│   ├── board.py
│   ├── new.py
│   └── VERSION
├── install.py
├── tests/
├── flatmark/                 # dogfooding instance installed via install.py
├── AGENTS.md                 # instructions for agents developing FlatMark
├── CONTRIBUTING.md
└── README.md
```

Acceptance criteria:
- [x] Payload files live in a dedicated directory; `install.py` (local and remote) copies from it.
- [x] `FLATMARK_RAW_URL` / default raw URL updated for the new path.
- [x] Existing tickets moved into the dogfooding `flatmark/` instance.
- [x] Root `AGENTS.md` rewritten for contributors (dev setup, tests, conventions, ticket usage).
- [x] `CONTRIBUTING.md` added.
- [x] Tests and CI updated; one-liner install verified.
