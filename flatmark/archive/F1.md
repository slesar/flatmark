# Prevent ticket ID collisions across parallel agents and branches

Sequential IDs are allocated by scanning local files. Two agents (or developers) working on
separate branches will both create e.g. `T5`, causing merge conflicts or duplicate IDs (B9).
This is the main scaling risk for multi-agent workflows.

Options to evaluate:
- Optional hash/short-random ID scheme (e.g. `T-7f3a`), configurable per project.
- Branch-aware suffixes.
- Documented convention: allocate IDs only on the main branch.

## Decision: Short Random Hash ID Scheme (`T-xxxx`)

### Evaluation of Options:
1. **Hash / Short-Random IDs (`T-xxxx`)**:
   - **Pros**: Completely decentralized. Agents on different branches can allocate tickets simultaneously with virtually zero probability of collision ($16^4 = 65,536$ combinations per prefix, automatically checked against existing tickets in `tickets/` and `archive/`).
   - **Cons**: Non-sequential numbering.
2. **Branch-Aware Suffixes (`T1-branch-name`)**:
   - **Pros**: Clear origin branch.
   - **Cons**: Verbose, fragile when branches rename/merge, and fails when multiple agents run in the same worktree or detached HEADs.
3. **Main-Branch-Only Allocation Convention**:
   - **Pros**: Sequential IDs preserved.
   - **Cons**: Severe bottleneck for autonomous agents on topic branches; requires continuous rebase and push locks.

### Chosen Implementation:
- **Adopt Option 1**: Decentralized short random hex IDs (`<prefix>-<4-hex>`, e.g. `T-7f3a`).
- **Configurable**: Configured via CLI flag `new.py --scheme random` (or `--random`).
- **Sequential Default**: `sequential` remains the default scheme (`T1`, `T2`) to ensure full backward compatibility.
- **Natural Sorting & Board Rendering**: `natural_sort_key` and hierarchy rendering in `board.py` fully support both numeric and alphanumeric IDs.

Acceptance criteria:
- [x] Decision documented (spike result in this ticket).
- [x] Chosen scheme implemented behind a config option; sequential remains the default.
- [x] Natural sorting and board rendering work with the new scheme.
